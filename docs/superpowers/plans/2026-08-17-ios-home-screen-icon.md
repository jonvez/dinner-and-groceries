# iOS Home-Screen Icon — Implementation Plan (#82)

**Goal:** Make the app installable to an iPhone home screen as a real-looking app — a proper icon and
a chrome-less (no URL bar) launch — so the teens open it from an icon instead of an oblique
`*.run.app` URL in a browser tab.

**Architecture:** Static assets plus Next.js Metadata API. No new dependency, no service worker, no
runtime code. The manifest is generated by `app/manifest.ts` (Next's `MetadataRoute.Manifest`
convention); the head tags come from `metadata` in `app/layout.tsx`.

**Tech stack:** Next 16.3.0 Metadata API, Playwright 1.61 (already a devDependency) for one-time
icon rasterization.

## Scope decisions (and what they rule out)

| Decision | Rationale |
|---|---|
| **iOS only** | Jon's call. Their phones are iPhones. |
| **No service worker** | A SW is required only for *Chrome's* install criteria (verified: Chrome's install algorithm still requires a `fetch` handler). iOS needs none. Dropping it removes the only security-sensitive part of this work — a SW intercepts every request including auth, and this app is entirely dynamic behind Google OAuth + RLS. Offline shell stays in M2. |
| **No maskable icon** | Maskable is an Android adaptive-icon concern. iOS applies its own mask to a full-bleed square. |
| **No custom domain (#83)** | Once installed, the URL is never typed again. First launch is solved by texting a link. #83 stays in the backlog for the productizing conversation. |
| **`statusBarStyle: "default"`** | NOT `black-translucent`, which draws content *under* the status bar and would put the app header behind the clock — we have no `env(safe-area-inset-*)` CSS. |

## Global constraints

- No new runtime dependency (icon generation uses the existing Playwright devDependency, and runs
  offline as a one-time script — its output is committed).
- Artwork is committed as PNG; `scripts/generate-icons.mjs` exists to reproduce it, not to run at build time.
- `apple-touch-icon.png` must be **opaque RGB with no alpha** — iOS composites a transparent touch
  icon onto black.
- Brand color of record: terracotta **`#C2410C`**. This is the app's first brand color; the palette
  is otherwise pure greyscale.
- All four required CI checks green; changes route through a PR.

## The prod footgun this plan must close

`public/` does not exist today, and **Next's standalone output does not copy it**. Two places drop it:

1. `Dockerfile:51-52` — carries a commented-out `COPY ... /app/public ./public` line left for exactly
   this moment. If it stays commented, **the image builds fine and every icon 404s in production.**
   The `Production build (Docker)` check would still be green. CI cannot catch this.
2. `package.json` → `start:standalone` copies `.next/static` but not `public/`, so the Playwright
   suite (which runs against the standalone server) would 404 the icons too.

Both are fixed in Task 1, and Task 3 adds guards so neither can silently regress.

### Task 2: Wire the manifest and the iOS head tags

**Files:**
- Create: `app/manifest.ts`
- Modify: `app/layout.tsx`

**Interfaces:**
- Produces: `/manifest.webmanifest` (Next's `app/manifest.ts` convention serves it at that path).

- [ ] **Step 1: Add `app/manifest.ts`**

```ts
import type { MetadataRoute } from "next";

export default function manifest(): MetadataRoute.Manifest {
  return {
    name: "Dinner & Groceries",
    // iOS truncates the home-screen label at ~12 characters.
    short_name: "Dinner",
    description:
      "Plan the family menu together, then let the grocery list flow from it.",
    start_url: "/",
    scope: "/",
    display: "standalone",
    background_color: "#ffffff",
    theme_color: "#C2410C",
    icons: [
      { src: "/icon-192.png", sizes: "192x192", type: "image/png" },
      { src: "/icon-512.png", sizes: "512x512", type: "image/png" },
    ],
  };
}
```

`background_color` is white to match the app's own background, so the launch flash doesn't strobe
terracotta before the UI paints.

- [ ] **Step 2: Extend `metadata` and `viewport` in `app/layout.tsx`**

```ts
export const metadata: Metadata = {
  title: "Dinner & Groceries",
  description:
    "Plan the family menu together, then let the grocery list flow from it.",
  manifest: "/manifest.webmanifest",
  icons: {
    icon: [
      { url: "/icon.svg", type: "image/svg+xml" },
      { url: "/icon-192.png", sizes: "192x192", type: "image/png" },
    ],
    apple: "/apple-touch-icon.png",
  },
  appleWebApp: {
    title: "Dinner",
    // "default" keeps the status bar its own layer. "black-translucent" would
    // draw the app under the clock, and we have no safe-area-inset CSS.
    statusBarStyle: "default",
  },
  other: {
    // Next's appleWebApp emits only the modern `mobile-web-app-capable`.
    // iOS below 16.4 honors only this legacy tag, and it is the switch that
    // removes the URL bar. One line of insurance.
    "apple-mobile-web-app-capable": "yes",
  },
};

export const viewport: Viewport = {
  themeColor: "#C2410C",
};
```

## Verification / acceptance

**Automated (CI):**
- lint + typecheck + unit tests pass, including the new Dockerfile guard
- Playwright smoke passes, including `e2e/pwa.spec.ts`
- All four required checks green

**Manual — Jon, on a real iPhone (the part CI cannot do):**
1. Open the app URL in Safari → Share → **Add to Home Screen**
2. The suggested name is **Dinner**, and the preview shows the plate icon (not a page screenshot)
3. Launch from the icon → **no URL bar, no Safari chrome**
4. Sign in with Google → lands back **inside** the app, still signed in
5. Force-quit and relaunch → still signed in

Step 4 is the real gate. Redirect-based OAuth from an installed iOS web app is the known failure
mode: standalone web apps historically kept a cookie jar separate from Safari, which broke the
round trip. Modern iOS handles it; this plan does not assume so.

## Rollback

Every change is additive except two one-line edits (`Dockerfile`, `start:standalone`). If the
installed app misbehaves, reverting the PR restores exactly today's behavior — the browser-tab
experience is unaffected by any of it.
