# Slice 1d · Story #15 — Shopping-list UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single editable `/grocery` list for the current week that pulls from the agreed menu (via #14's `buildGroceryList`) plus one-tap catalog staples and typed ad-hoc items, with a "we already have it" toggle, live cross-phone check-off (Realtime), and a "complete trip" that soft-archives checked items and offers new ad-hoc items for promotion into the staples catalog.

**Architecture:** A thin server component `app/grocery/page.tsx` resolves the current week (reusing the board's lazy-week resolver) and RLS-reads the active list + catalog via a unit-tested `list-core.ts`; a `"use client"` `grocery-list.tsx` renders it and merges live changes using the SAME Realtime authenticator + `reconcileByPk` pattern as `app/board/proposal-pool.tsx`. Mutations are thin `"use server"` actions over unit-tested `*-core.ts` orchestrators (injected client). Roll-up is #14's `buildGroceryListAction`.

**Tech Stack:** Next App Router server + client components, Supabase Realtime (`@supabase/ssr`), Vitest (cores), Playwright (two-client E2E).

## Global Constraints

- Editing the grocery list NEVER mutates dishes/recipes/ingredients (SPEC.md). `grocery_items` is independent.
- All reads/writes are RLS-scoped via `createServerComponentClient()`; household/member come ONLY from the actor resolver (`resolveGroceryActor`, #14). NEVER a service-role key; NEVER trust form input for household/member.
- Realtime channel is household-scoped: `` `grocery-list:${householdId}` `` with `filter: \`household_id=eq.${householdId}\``; the socket is authenticated via `createRealtimeAuthenticator`/`fetchRealtimeToken` from `@/lib/supabase/realtime-auth` BEFORE subscribing; reconcile by PK via `@/lib/social/reconcile`; re-fetch authoritative snapshot on reconnect.
- **Quantity/unit optional** everywhere — a member can add a bare name; render a missing quantity/unit as nothing, never "0" or "1".
- The active list = `grocery_items` for the current week WHERE `purchased_at is null`. Checked-and-archived rows carry `purchased_at`.
- Complete-trip promotion upserts `catalog_items` by `(household_id, lower(name))`; **accepting is an explicit step** (candidates are offered, not force-added).
- Co-located `*.test.ts`; `npm test`. E2E in `e2e/*.spec.ts`; `npm run test:e2e`.
- **Out of scope for #15 (deliberate):** free-form editing of an existing dish-derived row's quantity/name (which would set `edited=true`). Row protection in MVP comes from `have_it`/`checked`; the `edited` flag machinery already exists in #14 for a later "edit a grocery row" story — file it as backlog, don't build it here.

### Task 3: Mutation cores + actions (add / toggle)

**Files:** Create `app/grocery/mutations-core.ts` (+ `.test.ts`); extend `app/grocery/actions.ts`.

**Interfaces (each core takes `supabase: Pick<DbClient,"from">` + explicit `householdId`):**
- `addCatalogItemToList(supabase, { householdId, weekId, catalogItemId })` — inserts a `grocery_items` row `{ catalog_item_id, name/default_unit copied from the catalog row }`, and bumps that catalog row's `added_count`/`last_added_at`.
- `addAdHocItem(supabase, { householdId, weekId, name, quantity, unit })` — inserts a row with both feeder FKs null; `quantity`/`unit` optional.
- `setHaveIt(supabase, { id, haveIt })` — updates `have_it`.
- `setChecked(supabase, { id, checked })` — updates `checked`.

- [ ] **Step 1: Failing tests** (`mutations-core.test.ts`): assert each core issues the expected insert/update payload; `addCatalogItemToList` writes `catalog_item_id` + copies name/unit + increments `added_count`; `addAdHocItem` writes both FKs null and preserves null quantity/unit; toggles update only their column. Cross-household safety is enforced by RLS (covered in #13) — cores pass `household_id` on insert so RLS `with check` applies.
- [ ] **Step 2: Run, watch fail.**
- [ ] **Step 3: Implement `mutations-core.ts`**, then extend `actions.ts` with `"use server"` wrappers that resolve the actor, call the core, `revalidatePath("/grocery")`, and return a small state. Example:
```ts
export async function addAdHocItemAction(weekId: string, formData: FormData) {
  const supabase = await createServerComponentClient();
  const actor = await resolveGroceryActor(supabase);
  if (!actor) return { error: "Sign in to edit the list." };
  const name = String(formData.get("name") ?? "").trim();
  if (!name) return { error: "Give the item a name." };
  const rawQty = String(formData.get("quantity") ?? "").trim();
  const unit = String(formData.get("unit") ?? "").trim() || null;
  await addAdHocItem(supabase, {
    householdId: actor.householdId, weekId, name,
    quantity: rawQty === "" ? null : Number(rawQty), unit,
  });
  revalidatePath("/grocery");
  return { ok: true as const };
}
```
(Toggles: same shape; check-off/have-it actions revalidate and return `{ ok }`. The live UI updates optimistically + via Realtime; revalidate keeps SSR correct.)
- [ ] **Step 4: Run, pass; typecheck clean.**

### Task 4: Complete-trip + promotion

**Files:** Create `app/grocery/trip-core.ts` (+ `.test.ts`); extend `actions.ts`.

**Interfaces:**
- `completeTrip(supabase, { householdId, weekId }): Promise<{ archived: number; promotable: string[] }>` — sets `purchased_at = now()` on all checked, not-yet-purchased rows in the week; returns the count and the distinct names of archived **ad-hoc** rows (`ingredient_id is null and catalog_item_id is null`) as promotion candidates.
- `promoteToCatalog(supabase, { householdId, names }): Promise<void>` — for each name, upsert by `(household_id, lower(name))`: if a catalog row exists (case-insensitive), bump `added_count`/`last_added_at`; else insert a new catalog row (`added_count = 1`). Check-then-write in TS (RLS-scoped; no service-role).

- [ ] **Step 1: Failing tests** (`trip-core.test.ts`): `completeTrip` updates only checked+unpurchased rows with a timestamp and returns ad-hoc names (not dish-derived/catalog ones) as promotable; `promoteToCatalog` inserts a new catalog row for an unknown name and bumps `added_count` for a known one (case-insensitive match `"Olive Oil"` vs existing `"olive oil"`).
- [ ] **Step 2: Run, watch fail.**
- [ ] **Step 3: Implement.** `completeTrip`: `update grocery_items set purchased_at = now() where week_id=? and checked = true and purchased_at is null` (do it via the client: `.update({ purchased_at: new Date().toISOString() }).eq("week_id",weekId).eq("checked",true).is("purchased_at",null).select(...)` so the returned rows give counts + ad-hoc names). `promoteToCatalog`: per name, `.from("catalog_items").select("id,added_count").eq("household_id",hh).ilike("name",name).maybeSingle()` → update-or-insert. Then `actions.ts`:
  - `completeTripAction(weekId)` → resolve actor → `completeTrip` → `revalidatePath("/grocery")` → return `{ archived, promotable }`.
  - `promoteToCatalogAction(names: string[])` → resolve actor → `promoteToCatalog` → `revalidatePath("/grocery")` → `{ ok }`.
- [ ] **Step 4: Run, pass; typecheck clean.**
- [ ] **Step 5: Commit.** `feat(grocery): complete-trip archive + ad-hoc→catalog promotion (#15)`.
